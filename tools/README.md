# 构建管线（去指纹）

`_worker.js` 是唯一真源，**只改它**；`dist/_worker.js` 是构建产物，**不入库、不手工编辑**。
换字典值、换账号名、决定哪些字段连键名一起改，一律改 `tools/rules.mjs`。

## 目录

```
_worker.js        源文件（可读版，唯一真源）
wrangler.jsonc    部署配置（main = dist/_worker.js）
package.json      脚本入口
tools/
  rules.mjs       混淆规则表 —— 日常唯一需要手工维护的文件
  build.mjs       构建：_worker.js -> dist/_worker.js
  check.mjs       自检：漂移检测 + 语义等价证明 + 特征扫描
  lib/
    jsast.mjs     解析 / 遍历 / 常量折叠 / 归一化（build 与 check 共用）
    transform.mjs 变换管线（分析 + 应用编辑）
    scan.mjs      特征扫描与源/产物对比表
  README.md       本文件
```

## 日常流程

```bash
npm install          # 只有一个依赖：acorn（解析器）
npm run build        # 生成 dist/_worker.js，并打印统计与特征对比
npm run check        # 自检：任何一项不过都以非 0 退出
npm run deploy       # = build + check + wrangler deploy
npm run dev          # build + wrangler dev（本地起服务）
```

改完 `_worker.js` 或 `rules.mjs` 后，至少跑一次 `npm run verify`。
`check` 发现产物与重新构建的结果不一致时会直接判失败——这就是"不许手改 dist"的强制点。

## 每次构建都是新指纹

同一份 `_worker.js`，每次 `npm run build` 都会产出**不同但等价**的产物：

| 随机维度 | 效果 |
| --- | --- |
| 名池洗牌 + 短名起点 | 同一批变量每次映射到不同的短名（`qR` ↔ `f0` 随机互换） |
| 拆分切点轮次 | `'trojan'` 这次是 `'tro' + 'jan'`，下次是 `'troja' + 'n'` |
| 片段引号风格 | 单引号 / 双引号随机 |
| 片段呈现方式 | 字符串字面量 / 模板字面量随机（值一致） |
| 模板片段隐藏位置 | 哪些片段藏进 `${'…'}` 随机 |

配合源文件里的 `const Version = '…'`，**构建时间戳每次同步为本次构建时间**，
产物自带一个随部署变化的版本标记。种子与时间戳一起写进 `dist/_worker.build.json`，
所以 `check` 仍能逐字节复现产物（漂移检测不失效），也能顺手确认"换种子后产物确实变了且依然等价"。

```bash
node tools/build.mjs --seed 12345   # 指定种子，复现某一次构建
node tools/build.mjs --seed 0      # 关闭随机化，产物固定（便于逐行比对）
node tools/build.mjs --dry         # 只构建与自检，不写盘
```

实测：15 个不同种子连续构建，语义等价失败 0 次，相邻产物完全相同 0 次，
关键词类特征在每个种子下都保持 0 命中。

## 变换分两类，性质完全不同

### 一、值不变（可逆，语义等价）

| 变换 | 做什么 | 例子 |
| --- | --- | --- |
| 标识符改名 | 只改**绑定/引用**位置的标识符 | `forwardataTCP` → `f0`，`解析木马请求` → `qR` |
| 内部字段改名 | `rules.mjs` 点名的字段，连属性键一起改 | `{ rawClientData: x }` → `{ k9: x }` |
| 明文拆分 | 把关键词字面量切成拼接，值不变 | `'trojan'` → `'tro' + 'jan'`；正则 → `new RegExp('\\/' + 'tro' + 'jan=…', 'i')`；模板串 → `` `[木马反代] ` `` 插值 |
| 剥离注释 | 产物不含任何注释（注释里的中文说明也是指纹） | — |
| 空白收敛 | 去缩进、去空行；**跨行模板串内部原样保留** | — |

几条硬性设计：

- **属性键位置永远不改**（对象键、`.成员`、`obj['x']`、`Object.defineProperty` 的键）。这些是对外形状，
  关联着 KV 里的配置字段、HTTP 头名、订阅模板字段。只有 `rules.mjs` 里点名的"内部字段"才例外。
- **简写属性** `{ a }` 改名时展开成 `{ a: 新名 }`，键名不变；内部字段则 `{ 新名: 新名 }`，键一起改。
- **取名池**跳过源文件里已出现的所有名字，因此新名字不会捕获源文件里的变量。
- 字符串、正则、模板三种字面量都参与拆分；模板串靠 `${'片段'}` 插值藏词，值仍完全一致。
- **模板串里每个切点两侧至少一侧藏进插值**：否则相邻片段原样输出会把关键词重新拼成明文
  （`'invalid tr'` + `'oja'` 又拼回了 `trojan`）。这条约束是有代价的——随机化第一版就栽在这里，
  `check` 的特征扫描当场把它抓了出来。

### 二、值会变（不可逆，需要你确认）

`rules.mjs` 的 `字典值` 表会改字面量的**值**，直接影响订阅内容、请求路径、账号名。
每次构建都会逐条打印 `旧值 -> 新值`，`check` 会在等价性比对时把这部分差异按声明放过。
默认是空的——需要改什么自己加。

## `rules.mjs` 怎么用

```js
// 1) 换站点 / 账号名（会改变对外可见内容）
export const 字典值 = [
  { 匹配: 'https://edt-pages.github.io', 替换: 'https://你的域名.pages.dev' },
];

// 2) 决定哪些字段连键名一起改
//    前提：check.mjs 会校验该名字没有被当成字符串键使用（obj['x'] / defineProperty(o,'x')）。
//    若名字同时出现在日志/报错文案里，会给"提醒"（不阻断）；这类文案通常已被明文拆分顺手处理。
//    若名字其实是数据契约（例如要写进订阅、KV JSON），必须从这里移除。
export const 内部字段 = ['rawClientData', 'isUDP', 'hasError', 'respHeader', 'addressType', '木马反代地址'];

// 3) 补充要抹掉的明文关键词（子串匹配即可，不必写完整字面量）
export const 拆分关键词 = ['trojan', 'github.com', 'clash', ...];

// 4) 保留可读性 / 锁定名字 / 保护字面量
export const 排除标识符 = [];        // 这些名字不参与改名
export const 固定改名 = {};          // { 原名: 指定新名 }
export const 保护字面量 = ['use strict'];
```

选项（`选项` 对象）：

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `剥离注释` | true | 产物无注释 |
| `标识符改名` | true | 关掉则产物只做拆分与去注释 |
| `明文拆分` | true | 关掉则产物保留明文关键词 |
| `改名穿透属性键` | true | 某名字别处当过属性键时，其**局部绑定**仍改名（键名不动）。关掉更保守：凡出现过属性键的名字一律保留，代价是指纹残留从 0 涨到几十处 |
| `内部字段严格校验` | false | true = 内部字段的名字不得出现在任何字符串/模板/注释里 |

## 自检（`check.mjs`）做了什么

1. **漂移检测**：用 `dist/_worker.build.json` 里记录的种子与时间戳重建，与磁盘上的产物逐字节比对
   → 证明没人手改产物；同时核对产物哈希与源文件哈希。
2. **结构等价**：两份 AST 各自归一化后逐节点深比较。归一化做四件事：
   - 反向还原标识符改名与字典值替换（把产物"变回去"）；
   - 常量折叠：`'a' + 'b'`、`` `a` ``、`new RegExp('…','i')`、`globalThis['x']` 折成等值字面量/标识符；
   - 字符串拼接链与模板串统一成与括号层数无关的扁平序列（否则源文件写 `'a'+'b'+x`、
     产物写 `'a'+'b'+'c'+x` 会因树形不同而误判）；
   - 简写属性 `{a}` 与 `{a: _x}` 统一形态。
   只有规则表声明过的变换被允许存在，差异会打印第一处不同的完整路径。
3. **不变量**：内部字段前提成立；产物无注释、无 BOM、无 `debugger`；仍能解析且保留 `export default` 的 `fetch`；
   构建时间戳确实同步为本次构建时间。
4. **特征扫描**：与源文件并排对比（口径见 `rules.mjs` 的 `特征扫描`），任何特征"变多"即判失败。
5. **随机化**：换一个种子重建，断言产物**不同**且依然语义等价——这是"每次构建都是新指纹"的机器证明。

自检抓到过的真实缺陷（说明这套检查是有用的）：模板拆分把片段写重了导致字符串被污染、
简写属性带默认值时漏改、拼接链层数不同被误判为不等价、模板里相邻片段重新拼出 `trojan` 明文。

## 等价性证明的边界

`check` 能证明的是：**产物 = 源文件按规则表做的那几类变换，且没有别的差异**。
它不能替代运行时验证。上线前建议：

```bash
npm run dev     # 本地起 Worker，至少点一遍登录 / 订阅 / WS 连接
```

## 剩余特征为什么不去掉

这些是功能本身要求的，去掉就等于改行为：

- `new WebSocketPair()`：平台 API。可以改成 `globalThis['WebSocket' + 'Pair']`，
  归一化支持折叠这种写法，但属于运行期行为变更，默认不做。
- `env.PROXYIP` / `env.UUID` / `env.ADMIN` 等：与 dashboard 的变量名是契约，不能改。
- 占位 UUID、`/sub`、`token`、订阅转换参数名：对外路由与参数契约。
- `atob/btoa/fromCharCode`：功能实现需要。
- 53 端口分支、CF 常用端口列表、`pipeThrough`：协议与运行时细节。
